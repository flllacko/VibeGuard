# 宿主采集接到外部 HTTP 验收

日期：2026-10-21。复用现有三个 MCP 工具和运行器，没有增加桌面、安装包或新的平台适配器。

## 本轮补上的一环

已有 CLI 能要求执行时提供对话快照，但 Agent 仍可能传旧编号。现在外部执行通过以下链路：

用户独立发送验收命令 → Agent 申请执行已登记计划 → Hook 按宿主会话重新采集 → 保存两分钟有效的一次性凭据 → MCP 后台执行 → 同一工具查询原话、结果和证据。

外部执行即使带了 taskRef，Hook 也不再跳过采集；调用参数中的旧编号和旧凭据都会被替换。服务端缺少有效凭据就拒绝，不会把“工具调用成功”当作“验收通过”。普通要求整理和只读文件入口保持既有行为。

Codex 官方说明确认 PreToolUse 提供 session_id、tool_use_id 和工具参数，并支持改写输入或明确阻止调用；实现继续使用这一接口，不猜测聊天文件位置。依据：[官方 Hook 文档](https://learn.chatgpt.com/docs/hooks)。同一套处理数据与执行服务可由其他采集器复用，但实际支持仍以平台实测为准。

## 用户怎样用

本阶段仍须先配置项目运行方式、确认要求并登记外部 HTTP 计划；尚未自动发现任意项目或替用户准备所有运行配置。

准备完成后，在原 Agent 独立发送：

```text
用 VibeGuard 验收
```

Agent 内部调用 `verify_task({externalPlanRef: 已登记计划编号})`。Hook 自动补入当前 taskRef 和 captureTicket，用户不需要每次复制聊天或手填采集编号。工具返回运行编号后，用 `get_verification` 查询；`includeReport=true` 返回可读 text、原话、覆盖缺口及实际观察，`read_evidence` 按该运行读证据。

**这是固定产品命令，不是新增业务关键词判断。** 只有这条独立命令走无模型快路径，原文保留并记作验收请求，不改动业务要求。自然修订仍由现有修订模型理解，不为每个业务加句式分支。

“用 VibeGuard 验收，另加一个功能”、转述中的命令、此前尚未处理的用户消息，均不能走快捷路径，应先走要求审查。多次独立验收命令可保留在历史里，最新一条的消息身份决定本次请求；不会删除用户消息来假装对话没有变化。

## 各部分职责

| 部分 | 负责什么 |
| --- | --- |
| 平台采集 Hook | 使用宿主当前会话身份重新读取材料，校验独立请求，绑定已登记计划 |
| 一次性凭据 | 绑定计划、采集摘要、会话、工具调用身份和 scope；两分钟有效，消费写入独占记录 |
| MCP 服务 | 拒绝缺失/不匹配/重复凭据；创建后台运行，运行中或无法确定均不通过 |
| Core 与运行器 | 按固定交付和标准实际检查、保存原始证据并给出结论 |
| 查询工具 | 校验运行与源材料绑定，返回逐条有效结论和原始证据片段 |

凭据不能包含用户自填的 verdict 或检查输出。它是本地接入账目，不是平台签名，也不抵御同账户改写整套数据。它不代替真实执行证据。

同一用户请求、同一计划及 scope，重新采集后复用已有任务记录，不重复启动容器；直接重放旧凭据被拒。要再次验收，发送新的独立命令。外部模式不接受 forceRerun 或与要求修订混用，以免一个工具参数绕过请求去重。

`--codex-thread` 固定会话开发入口也可由服务端独立采集；没有 Hook 或固定会话采集时，手填 taskRef 不足以启动 MCP 外部执行。普通 CLI 的显式快照开发入口仍可用，不冒充宿主自动采集。

## 代码与配置影响

- 新增 `acceptance-command.ts` 和 `host-execution-ticket.ts`，将请求身份和业务标准分开。
- 原 `verify_task` 增加 externalPlanRef、captureTicket；三个工具名称不变，原 Hook 匹配器不变。
- `VerificationService` 增加后台外部运行与历史/证据查询；运行未完整结束时逐条结论也保持无法验证，不把中间成功抬成最终通过。
- 执行快照保存验收请求原话与消息编号，读取时检查它仍对应真实保存的用户消息。
- 本轮没有改全局 MCP/Hook 配置。源码构建后长驻 MCP 仍需重载才能获得新参数；保持同一 Hook 命令路径不代表已证明当前桌面宿主运行了新流程。

## 实测了什么

[合成服务样本](../fixtures/evaluations/d3-host-bridge.json)要求身份接口返回指定字段。Flash 真实规划一次，输入只含原话、引用和接口契约，不含源码、变体标签、其他聊天或独立答案。得到 service 和 revision 两项实际断言，同一计划重新绑定两份交付。

宿主 Hook 载荷与采集回调由测试程序模拟；**MCP stdio 子进程、后台任务、Docker、HTTP 观察与证据读回均实际执行**。不得把这里写成当前 Codex 桌面已自动采集并完成真人验收。

| 交付 | 实际响应 | MCP 结论 | MCP 运行编号 |
| --- | --- | --- | --- |
| 正确 | HTTP 200；service=atlas-worker，revision=7 | VERIFIED | `5d3345e0-e58d-8119-aabe-439c172a1a1c` |
| 有缺陷 | HTTP 200；revision 实际 8，冻结预期 7 | FAILED | `ff37a294-9fe2-8441-afe8-3aa78cdde3d3` |

缺陷证据编号 `97b2a197-8530-48f8-9dc5-7375ccc15515`。对应 CLI 外部运行编号为 `e559f247-84f7-40c9-a8c5-c34db0634fe2`；MCP 的 runId 是后台任务编号，界面应自动传递，不要求用户区分两类内部编号。

重放凭据均被拒；每份交付换新凭据重试仍复用该任务，实际外部运行目录只有两份。重启 MCP 后，在不带本项目模型密钥、PATH 无 Docker 的进程读取两份报告和两条证据成功。

真实容器执行期间十个源码文件哈希一致；随后补充了未完整结束时的逐条结论视图，构建后又用新 MCP 进程读回这两份记录核对。没有修改既有证据或测试标准。容器和临时镜像均已清理。

构建和 **162 项测试通过**，最终接入测试另复验六项。覆盖旧编号替换、混合改口、采集故障不回退、过期、并发消费、重放、去重、服务重启和无 Docker 时无法验证。模拟工具响应不作为上表证据。

本轮真实模型 **1 次响应，880 输入 / 220 输出 token，SDK 估算 $0.000377472**，非账单。没有格式重试；第二份交付复用计划，不产生额外规划调用。MCP 执行与读回子进程没有模型密钥。

## 还没证明什么

当前桌面宿主自动触发 Hook、实际提供工具调用身份并交付当前会话材料，尚未实测。原生连接仍可能加载旧 MCP，必须先核对重载后的参数；真实采集若有范围、分页或附件缺口，应停止而不是套用本次合成完整材料。

这里的短期凭据只能约束本地接入路径，不是“任意 Agent 无法伪造”的密码学证明。也没有实现对任意仓库自动启动、自动生成项目配置、桌面安装包、新平台、浏览器或数据库检查。

后续已完成新进程接口自检及当前真实聊天显式采集；原生连接仍暴露旧参数，须重载后核对。观察及剩余动作见[原生连接核对](28-native-connection-audit.md)，不宣传“已全自动接入”。
