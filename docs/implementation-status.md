## 当前边界

- M1 的验收计划是手写的，只检查优惠券门槛。正确版本的门槛范围可标 `VERIFIED`，但整个任务因“一次使用”未验证仍为 `UNVERIFIABLE`。
- 运行的是本项目自编受控样例。Docker 已可连接，但当前代码尚未使用容器运行待验收交付；不能宣称任意外部 Agent 代码已被安全隔离。
- 当前终端没有 `claude` 命令，不影响通用 Core/CLI。首个自动接入宿主按完整对话与收尾事件能力实测决定。
- 用户指定 DeepSeek Flash 为默认模型；Windows 用户变量中有 DeepSeek 凭据，当前已打开的 Codex 进程不会自动继承，需要在临时子进程读取用户变量或重启 Codex。不要在聊天中传递密钥。
- M2 的真实 Flash 样例得到两条当前要求和一条取消要求；只有一个公开样例，不能宣称要求抽取普遍准确。先前 Pro 响应把多条要求合并，证明需要持续评估语义漏检。
- M3 的计划样例由人手写。虽然程序能拒绝漏项和执行计划，但尚不能宣称模型会自动想出 150/149 等验收条件。计划中的自然语言前置条件未全部机器核对，受控样例之外不能扩大结论。
- `plan` 的真实 Flash 候选计划把成功结算预期状态写成 200，实际演示 API 返回 201；且跨检查重复使用同一张券，使门槛反例可能被“券已用过”解释。结构冻结不等于可执行的可信计划，尚未拿它验收交付。
- `deepseek`、`kimi`、`kimi-global` 已有 CLI 默认模型；DeepSeek Flash 单样例实测，Kimi 未实测。豆包、硅基流动、百炼仍未接入。
- 本地证据文件带哈希，能发现读取时的文件变化；与干活 Agent 共享写入权限时，不能防止其同时改写证据与清单，尚不满足强隔离的防伪主张。
