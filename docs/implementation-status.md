## 当前边界

- M1 的验收计划是手写的，只检查优惠券门槛。正确版本的门槛范围可标 `VERIFIED`，但整个任务因“一次使用”未验证仍为 `UNVERIFIABLE`。
- 运行的是本项目自编受控样例。Docker 已可连接，但当前代码尚未使用容器运行待验收交付；不能宣称任意外部 Agent 代码已被安全隔离。
- 当前终端没有 `claude` 命令，不影响通用 Core/CLI/MCP。首个主动接入宿主按完整对话、工具调用与结果显示能力实测决定；自动收尾另验。
- 用户指定 DeepSeek Flash 为默认模型；Codex 重启后已直接识别 Windows 用户变量中的 DeepSeek 凭据。不要在聊天中传递密钥。
- M2 的公开 Flash 样例得到两条当前要求和一条取消要求；另有两份保留的合成对话由人工标准答案复核，均符合本次预期。样本数量很小，不能宣称要求抽取普遍准确。先前 Pro 响应把多条要求合并，证明需要持续评估语义漏检。
- 真实 Codex 长任务试点已导入 25 条用户消息及 72 条助手可见消息，材料因当前会话仍在进行且不含工具事件而标为 `partial`。DeepSeek Flash 两次较大批次尝试分别因 JSON 格式错误、消息分类与事件矛盾停下；缩小批次后 25 条均有处理去向，但仍有 4 条歧义，55 项候选中包含误把转述第三方主张当作用户采纳的要求。逐字引用校验不能发现这种语义误判；原始阶段记录保存在 `.vibeguard/evaluations/real-codex-long-task-20260929.md`。
- 2026-09-29 的后续复测增加外部引文范围与用户采纳依据检查，区分响应注释中的 Assistant 原文和用户评论，缩小默认分块，允许有限的 JSON 尾逗号格式修复及一次程序校验后的重新提议。运行 `78617ba7-c095-4728-bff9-8281dc694edb` 处理所导入的 25/25 条用户消息、8 块均成功；未发现把“必须签名/透明日志”列成当前要求，仍有 1 条用户消息标为未确定。该快照的最后一条可见消息还在 2026-09-29 开工指令之前；因此旧的“先不要大量写代码”留在 active **不能直接归因于模型漏撤销**。材料标记为 `partial`，不能宣称真实长对话的当前要求已整理正确。原始结果在 `.vibeguard/evaluations/real-long-task-after-provenance.json`。
- M3 已有人工、公开真实模型、保留新任务三个受控样例。前一份真实计划把 201 写成 200 并重复用券；新增 API 契约状态和跨检查数据隔离门禁后，新计划通过并实际执行。保留新任务在四种实现得到预期结论，详见 `docs/heldout-evaluation-2026-09-29.md`。计划中的自然语言前置条件未全部由机器核对；模型预期值错误仍可能造成误报。
- `deepseek`、`kimi`、`kimi-global` 已有 CLI 默认模型；DeepSeek Flash 单样例实测，Kimi 未实测。豆包、硅基流动、百炼仍未接入。
- 本地证据文件带哈希，能发现读取时的文件变化；与干活 Agent 共享写入权限时，不能防止其同时改写证据与清单，尚不满足强隔离的防伪主张。
- MCP 协议本身不提供历史；Codex 专用采集器现可通过官方接口读历史，启动配置绑定本条会话时允许省略 taskRef 自动采集。其他宿主仍需采集或导入。普通外部任务没有执行能力；内置受控样例可绑定计划实际执行。阶段范围目前只是 `checkpoint/final` 标签，尚不自动选择阶段要求，也不绑定外部工作树快照。相同 taskRef 的重用不会自动发现新代码。
