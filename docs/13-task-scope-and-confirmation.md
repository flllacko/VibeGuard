# 长聊天中选择本次验收范围

日期：2026-10-14。当前为源码原型；真实长对话已生成候选，真实用户选择已通过宿主采集和新 MCP 进程核对。整体验收仍停在材料缺口，未通过业务验收。

## 用户看到什么

正常工作时继续在原 Agent 聊天提需求。需要验收时说“用 VibeGuard 验收刚才这项任务”。

已登记且范围明确的任务沿用原流程。新采集的 Codex 长聊天如尚未确定范围，会先返回候选：

> 本次可能是“修改密码”。
>
> 用户原话：“增加修改密码功能。”
>
> 带入前文：“后续功能都要保留登录状态。”
>
> 主体范围：提出修改密码 → Agent 的相关交付。
>
> 请确认这个范围，或说明需要调整到哪一阶段。

这是模拟界面文字。实际候选附原消息编号、逐字来源、起止摘录、带入前文和歧义。用户可通过选择框提交该候选的 `confirmationReply`；短编号将这次选择与这份清单绑定，避免把上次“同意”误套过来。当前回复格式较严格，尚不支持可靠理解任意一句“就这个”。

选择后仍要整理有效要求、生成验收标准、执行取证。确认范围本身不会产生“已验证”。

## 原文怎么保留

1. 采集器保存宿主原始响应、全部已采集文字与哈希。
2. 独立模型从原文提出候选。长消息 ID 临时映射为 M1、M2 等；文字不缩写，输出再由程序还原原始 ID。
3. 程序核对开始必须是用户消息、首尾顺序、前文位置和逐字引文。模型不能提交通过、人工确认或材料完整字段。
4. 原聊天的下一条真实用户消息选择范围。钩子重新采集同一会话，程序核对原文前缀一致、只有一条新用户回复、回复匹配本次清单。
5. 创建派生任务：保留选中主体和相关前文，消息 ID 和文字不变；连续编号只用于处理，另外保存原始编号映射、父快照和确认来源。原始整段聊天不会被覆盖。
6. 需求整理器收到主体与前文的角色标记，只提取本次任务及仍适用的旧约束。语义仍可能漏选或误判，用户应能要求调整。

用户在确认之前又增加了要求，程序会拒绝沿用旧候选，需要根据新原文重新整理。模型不能靠工具参数 `confirmed: true` 绕过确认。

## 材料完整与范围确认分别判断

| 情况 | 后续处理 |
| --- | --- |
| 原始任务材料已声明完整 | 在所选范围内继承声明；仍不是功能通过 |
| 新 Codex 采集已读完此次返回的 full 分页，所选主体和前文没有未解析内容，消息账目连续 | 可以进入所选文字范围的要求整理，保留来源限制 |
| 所选内容包含未解析图片、缺页、缺消息或不明来源 | 材料仍不足；仅前文附件缺口且来源账目充分时，可继续整理文字候选，见文档 14。正文附件或不明来源继续阻断 |
| 图片仅属于未选中的另一项旧任务 | 不据此阻断所选文字任务；旧整段快照仍是 partial |
| 老版快照没有逐消息非文字账目，或 Claude SDK 历史存在压缩/分支缺口 | 选择范围不能把它改为完整；重新采集或补材料 |

Codex 的 `allReturnedPagesRead` 只说明读完宿主此次提供的页面，不是对所有历史、分支和图片语义的绝对保证。`scopeOnlyGap` 表示采集器可定位的范围缺口；未解析非文字内容另按消息记录。模型挑出了范围，也不能证明没有漏掉相关旧要求。

## MCP 调用约定

仍是三个工具，无需额外安装一个范围插件。

第一次 `verify_task`：钩子登记当前原文，返回运行编号；查询 `get_verification` 后可能出现：

```json
{
  "verdict": "UNVERIFIABLE",
  "gapStage": "scope",
  "taskScopeReview": {
    "status": "needs_scope_confirmation",
    "proposalRef": "内部清单编号",
    "candidates": [{
      "candidateId": "S1",
      "title": "修改密码",
      "confirmationReply": "验收范围 S1 本次短编号"
    }]
  }
}
```

上例为字段示意，实际 UUID 由系统生成。Agent 展示候选，取得真实用户选择后再次调用：

```json
{
  "taskSelection": {
    "proposalRef": "上次返回的真实 UUID",
    "candidateId": "S1"
  }
}
```

钩子会重新采集；即使 Agent 传了旧 taskRef，也必须更新为当前快照。确认来自新原文，工具参数只指向候选。没有钩子时必须通过可信采集器登记新快照，不能让干活 Agent 自写一份确认对话。

运行中的旧 MCP 进程需要重载以识别新参数。这次修改不要求重写已有平台配置；新钩子代码随源码构建生效，平台对钩子代码变更的信任要求仍按平台处理。

## 开发者复现

```powershell
pnpm build
node dist/cli.js capture-codex <当前聊天UUID>
node dist/cli.js verify-task <得到的taskRef>
node dist/cli.js scope-review <返回的proposalRef>
# 用户在原聊天选择后，重新 capture-codex，使用新的 taskRef
node dist/cli.js verify-task <新taskRef> --scope-proposal <proposalRef> --candidate S1
```

自动范围提议目前接在具备分页与内容账目的 Codex 采集之后。共用的候选校验、确认和存储模块不绑定 Codex；其他采集器仍需补足自己的材料账目，不能宣传所有平台已实测。

独立模型默认 DeepSeek Flash，读取已配置的环境变量。单次范围提议最多调用两次（一次候选、一次校验反馈修正），网络失败不自动重试；超出 220,000 字符输入预算时明确停止，不截断。相同原文与模型策略复用候选，范围变化后重新生成。输入 Token 统计包含缓存读取/写入，模型价目估算不等于实际账单。
