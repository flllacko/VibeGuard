# VibeGuard 工程决定

更新时间：2026-09-28。以下区分客户已确认方向和实施中的临时决定。

| 决定 | 原因 | 状态 |
| --- | --- | --- |
| TypeScript + Node.js 为主语言和运行环境 | 统一 Core、CLI、MCP、浏览器工具和接入层 | 已确认方向 |
| Jev、Laya 只用于后续优化实验 | 是否节省完整链路成本、是否影响漏检仍须实测 | 已确认方向 |
| Core/CLI 使用规范化完整对话作为首个输入 | 不依赖任何宿主先验证“要求到证据”的能力 | 实施决定 |
| 首个自动接入宿主按真实环境与能力选择 | 当前没有 claude 命令；产品定位跨 Agent | 实施决定，待 M0 验证 |
| M1 只运行本项目自编、可控样例 | Docker 已可连接，但外部代码隔离运行器尚未实现 | 当前开发边界 |
| 主模型与凭据 | 当前未检查到可用项目配置，不能宣称模型验收已实现 | 待确定 |
| M2 使用 Pi 官方 `@earendil-works/pi-ai` 0.87.1 | 当前官方包已采用 `@earendil-works` 命名；先调用模型，不引入完整 Agent 运行循环 | 实施决定 |
| 禁用暂不需要的 Google/protobuf 传递依赖构建脚本 | pnpm 11 默认要求对构建脚本明确决策；当前优先验证 OpenAI 路径 | 实施决定，启用其他提供商前复核 |
