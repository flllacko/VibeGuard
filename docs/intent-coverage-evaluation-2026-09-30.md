## 改了什么

此前仅检查“每条用户消息是否处理过”，一句话里的多项要求仍可能漏掉。

现在增加：

    用户原话分段
      → 要求 / 操作授权 / 背景或讨论 / 待确认
      → 对应的要求 ID 与拆分结果
      → 验收计划和执行证据（后续阶段）

程序生成分段并逐字保存；模型一次输出要求事件及各段去向。漏段、重复分段、无对应要求或授权同时生成新目标会被拒绝；仍待确认的片段让整理保持不完整。简短编号及默认只回传计数控制附加上下文，详细原文按需查看。

## 本轮也发现并处理的工程问题

- 模型把可选 adoption 写成 null 时，原先会重复失败。现在 null 表示没有采纳引用；外部引文仍必须有真实用户采纳依据才能进入要求，不放宽来源门禁。
- “不要代提交”和紧邻的“我自己弄这个”可以重申同一规则，不能因引用只落在前一段就重复建任务。现在保留重申原话并关联原 ID。
- 模型格式重试会收到具体字段错误；有限重试仍失败时保留缺口。
- 整理规则改变后，运行复用键随之变化，避免继续拿旧的整理当新版结果。已启动的宿主 MCP 进程仍需重载代码，本轮没有修改平台配置。

首次复测失败记录 `skill-intent-retest.json`、`school-intent-retest.json` 保留在本机，不用后来的成功覆盖失败历史。
