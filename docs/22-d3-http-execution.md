# D3：冻结计划实际执行与证据重启读回

日期：2026-10-20。本轮只推进 D3；沿用引擎、桌面验收台、MCP 接入的形态，没有开发新界面或平台接入。

## 本轮补上的一环

原来只能生成计划，或证明项目能启动。本轮让同一冻结计划在 Docker 就绪后、资源清理前执行：

原话与确认要求 → 标准/HTTP 计划 → 绑定固定交付 → 容器启动/就绪 → 固定采集程序发出请求 → 验收进程核对断言 → 逐步证据落盘 → 汇总三态 → 清理 → 新进程读取。

不让待测应用自己报告“通过”。模型只能提出请求、预期和覆盖去向，不能提交 verdict 或执行结果。请求数据单独编码，模型不能传入可执行脚本。没有真实观察的步骤不能已验证。

## 支持范围与限制

- 2026-10-20 后续增量：支持明确引用前一步捕获值的等值断言，模型候选校验失败最多反馈修正一次，各次用量累计；认证、网络和不完整响应不重试。真实有状态任务、失败记录及旧计划兼容见 [增量实测](23-stateful-http-evaluation.md)。下文 230/30 数据是首次交付当时的历史记录。
- 沿用 D2：官方 Node 24 缓存镜像、直接 JavaScript 入口、无需安装依赖的交付。源码只读、无外网、没有宿主目录/证据库/Docker socket 挂载。
- GET/POST、JSON 等值断言、顺序步骤与响应字段捕获。每次最多 40 项检查、80 个步骤，功能执行默认最多 120 秒。
- 请求上限 8 KiB，响应上限 64 KiB；不跟随重定向。超限、超时、取消、工具错误或未完成步骤输出无法验证，并保留实际错误。
- 自然语言前置条件没有被步骤核对时，即使其他断言满足也不能已验证。数据准备应写成明确步骤，不以一句“数据已就绪”冒充事实。
- 所有功能检查先完成再清理。清理未确认或生命周期未完整结束时，整体不能已验证；已取得的观察仍保留。
- 同容器采集不承诺抵御任意恶意进程干扰。本地摘要也不抵御同权限进程重写整套材料。
- 浏览器、数据库、请求头认证、依赖安装和并发检查均未执行，属于本轮范围之外。

## 本轮三个实际演示

用户在本轮实现后提供的测试原话：

> 做一个 HTTP 接口，接收一个整数 amount（订单金额，单位元）。amount 大于等于 230 时返回 JSON {"discount": 30}，小于 230 时返回 {"discount": 0}。

接口契约只给方法、路径、单位与 JSON 结构。真实 Flash 自行生成 230、1000、229、0 四个输入及相应预期。产品执行代码没有加入这些业务数值；测试交付和独立参考答案位于 [评估样本](../fixtures/evaluations/d3-user-amount-230.json)，不发送给模型。

| 交付 | 实际观察 | 本次计划结论 | 外部运行编号 |
| --- | --- | --- | --- |
| 正确实现 | 230→30、229→0、1000→30、0→0，均 HTTP 200 | VERIFIED | `451ac6e3-4e2f-42a2-90bc-2a4c3a35d394` |
| 有缺陷实现 | 230 实际返回 0，冻结预期为 30；其他三项符合预期 | FAILED | `d2ba9812-213b-482d-af8b-35b3704541cd` |
| 不可用实现 | 程序实际退出码 9，没有功能 HTTP 观察 | UNVERIFIABLE | `37180d13-670a-4e1f-bf8f-138b0b0f77df` |

三份交付使用相同的标准、步骤与预期，分别重新绑定要求及交付版本，计划摘要与交付摘要不冒充相同。后两份复用首次真实模型计划内容，没有额外模型调用。执行前后六个核心文件哈希一致；没有在看到结果后修改产品代码或正确答案。

一次 DeepSeek 官方 `deepseek-flash` 调用：761 输入、612 输出 token，SDK 估算费用 **$0.0009627**，不是供应商账单。首次联网被自动审批拒绝，用户明确批准这份材料后才发送；被拒操作没有调用模型。没有发送之前的长聊天、源码、变体标签、参考答案或密钥正文。原始模型响应和用量保存在 `planner-attempts`。

原验证进程退出后，另起不带模型密钥、PATH 不含 Docker 的 Node 进程，三份报告和八条功能证据全部成功读回。不可用案例另外从运行记录读回退出码 9。Docker 标签查询未发现本工具残留容器或临时镜像。

这证明了本次样本的真实模型规划、容器功能执行、三态与持久读回；不证明任意新任务普遍准确。单条要求输入与确认是评估程序预置，**不计为真实宿主的对话提取、真人要求审查或 MCP 接入验收**。

## 怎么自己查看

在仓库目录运行：

```powershell
# 直接展示失败原因、原话、实际观察和证据编号
node dist/cli.js project-report d2ba9812-213b-482d-af8b-35b3704541cd --data-dir .vibeguard/evaluations/d3-user-230-20261020-first/data

# 读取“230 实际返回 0”的原始请求、响应及运行记录引用
node dist/cli.js project-evidence d2ba9812-213b-482d-af8b-35b3704541cd 479959ff-5169-4790-bc5f-225b7a2ca072 --data-dir .vibeguard/evaluations/d3-user-230-20261020-first/data
```

正常开发使用：

```powershell
node dist/cli.js project-run PLAN_REF --data-dir DATA_DIR
node dist/cli.js project-report RUN_ID --data-dir DATA_DIR
node dist/cli.js project-evidence RUN_ID EVIDENCE_ID --data-dir DATA_DIR
```

`project-run` 启动交付并执行；另外两项只读本地记录，不调用模型或 Docker。退出码沿用三态规则：已验证 0、失败 1、无法验证 2。

本机原始资料位于 `.vibeguard/evaluations/d3-user-230-20261020-first/`：`summary.json`、三份 `*-report.md`、`outgoing-review.md`、`real-model-plan.json`、`restarted-readback.json`、实现前后摘要及 `data/`。此目录被 Git 忽略，不随源码提交。

## 证据保存和中断

`external-runs/RUN_ID/start.json` 保存当时的计划、来源要求及摘要。每个已经产生的观察立即写入 `observations/EVIDENCE_ID.json`；结束时关联运行器记录和已有 `planned-runs` 证据，写 `finish.json`。

读取会核对摘要、运行/交付关系、观察编号、请求参数与原始响应字节。历史报告使用当时归档，不因后续源码或要求变化而冒充新版本通过，也不会因此失去旧证据。

没有完成记录时，只展示已保存片段并标无法验证，不能推测任务通过。硬杀进程或断电仍可能留下容器，自动发现和恢复清理尚未实现；当前正常结束和请求取消的清理已测试。
