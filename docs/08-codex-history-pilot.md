## 权限分别控制什么

- Agent 的审批、沙箱和“完全访问”设置控制其工具执行范围，不能代替 MCP 接入或提供原始聊天。
- VibeGuard 采集器需要能启动本地 Codex 程序并读取授权会话的记录；实际能力由安装方式、操作系统和宿主配置共同决定。
- 持久接入须由用户同意添加 MCP 配置。如果使用 Codex Hook，官方另外要求用户审查并信任具体钩子；安装插件不自动等于信任钩子。

本机现有配置为 `danger-full-access` 与 `approval_policy = never`。本次没有改变它们，读取过程没有请求权限升级；这**不能证明默认受限模式也已实测通过**。后续应单独验证受限模式、无法读取和权限撤回。当前只启动独立的本地读取进程，不通过 UI 修改安全设置。

依据：[Codex App Server](https://learn.chatgpt.com/docs/app-server)、[MCP 配置](https://learn.chatgpt.com/docs/extend/mcp)、[Hook 信任](https://learn.chatgpt.com/docs/hooks)。

## 已实现的数据路径

采集器只发送 `initialize`、`thread/read` 和 `thread/turns/list`；不会调用恢复会话、启动新轮次、执行命令或修改聊天的接口。

1. 用明确授权的会话编号读取已保存历史。
2. 按时间顺序读完 `itemsView: full` 的所有页面；摘要页、重复分页、已知消息缺失或用户原文变化会停止采集。
3. 将边界固定到读取开始时最后一条用户消息；本轮随后产生的验收工具输出不混入这份输入。
4. 保存原始 API 响应、规范化用户/助手原文与采集收据，再登记 taskRef。

完整原始响应中的工具记录留在 `raw.json`，不会当作 VibeGuard 新执行的完成证据。规范化对话只放用户与助手消息；非文字用户内容保留在原始响应并列为解析缺口。

`allPagesRead: true` 表示读完本次宿主返回的历史；`taskScopeConfirmed: false` 表示尚未确认具体任务范围。因此当前规范化材料仍标 `partial`。它不是“没读到聊天”，也不代表这条长期项目对话中的所有要求都已交付。下一步需要把会话材料中的任务起止范围与交付快照明确绑定；当前没有让 Agent 自行把这个标记改成 complete 的入口。

## 现在可重复运行的命令

```powershell
node dist/cli.js capture-codex <会话编号>
```

默认阶段标签为 `checkpoint`，可传 `--scope final`；这个标签不会自动筛掉未到阶段的要求。若当前终端找不到 Codex，使用 `--codex-bin <Codex可执行文件绝对路径>`。命令只做本地采集与登记，不调用模型，也不打印整段原始聊天。

## MCP 当前会话试点

在服务启动参数中加入 `--codex-thread <会话编号>`，必要时加入 `--codex-bin <路径>`。之后 `verify_task` 可不传 taskRef，由采集器自动读取该绑定会话并登记新快照；原有传 taskRef 的调用保持有效。

这次服务绑定的是明确的单条会话。**它不是任意新聊天的自动发现机制**；不依据“最新修改的日志”猜测当前会话。下一阶段由平台事件提供当前会话身份，配置助手负责安装和诊断该入口；不能将本次固定编号试点宣传成所有聊天已经一键接入。

工具参数不接受其他 threadId、文件路径或 verdict，绑定只能由服务启动配置决定。省略 taskRef 会重新采集并登记快照；同一 taskRef 仍可复用验收记录。因任务范围未确认，本次材料检查返回 `UNVERIFIABLE`，不消耗模型调用。

早期拟添加的固定会话条目保存在本地 `.vibeguard/integration-proposals/codex-current-session.toml`，未生效。用户现已选择自行配置，无需由 Codex 备份或修改该文件。优先按新接入说明通过界面添加 MCP，再审查动态采集 Hook；不要把早期固定编号条目当成任意聊天都能通用的配置。
